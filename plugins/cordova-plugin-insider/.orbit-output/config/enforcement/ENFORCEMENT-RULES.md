## Session-start protocol

Before any code task in this repo:
1. Read `.orbit-output/config/MASTER.md`.
2. Consult `ARCHITECTURE.md` / `CODE-CATALOG.md` / `API_DOCS.md` for the area you're touching.
3. Follow `CODING.md`, `.claude/rules/unit-tests.md`, and `.claude/rules/git-workflow.md`.

## Hard rules (must hold)

1. **Single native call path** — all native invocations go through `Utils.asyncExec(Constants.CLASS, reference, args)`. No direct `cordova.exec`.
2. **Validate-first** — every public method runs `Utils.checkParameters([...])` and bails with `showParameterWarningLog` before any native call.
3. **Central constants** — native action names only in `js/Constants.js`; no inline action strings.
4. **Cross-platform parity** — a new public API requires JS + `src/android` handler + `src/ios` handler + `types/*.d.ts`.
5. **Bridge serialization** — objects via `parseObjectWithTypes`; dates as epoch-ms strings; consent/collection booleans as lowercased strings.
6. **Error routing** — caught errors go to native via `PUT_ERROR_LOG`.
7. **Test coverage** — no behavior change without a corresponding Jest test; `npm test` green before PR.
8. **Generated output is off-limits** — never hand-edit `www/` (build output) or `.orbit-output/` (regenerate via `/orbit:init` or `/orbit:sync`).
9. **Version sync on release** — `package.json`, `Constants.SDK_VERSION`, `plugin.xml` pods, `build-extras.gradle` pins move together.

## Keeping analysis fresh

If you change structure (new module, new layer, moved files), update `.orbit-output/config/architecture/` — run `/orbit:sync` (or `/orbit:init` for a full refresh). Orbit commit hooks may block commits when `.orbit-output/` is stale relative to code changes.
