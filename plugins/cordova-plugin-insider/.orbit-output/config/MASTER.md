## What this is

`cordova-plugin-insider` is a **Cordova plugin** (npm package `cordova-plugin-insider`) that wraps the Insider Mobile SDK for iOS and Android and exposes it to Cordova/hybrid apps as the global `Insider` object. Team: **mobile.sdk**.

## How it is built

Three layers:

```
JS app → js/ (bridge, built to www/) → cordova.exec → src/android (Java) / src/ios (ObjC) → Insider native SDK
                                              ↑ Promise              ↓ cordova.fireDocumentEvent (callbacks)
```

- **JS bridge** (`js/`): validates input, serializes to a typed bridge contract, calls native via `Utils.asyncExec`. Entry: `js/InsiderPlugin.js` (singleton, clobbered onto `Insider`).
- **Native** (`src/android` Java `CordovaPlugin`, `src/ios` ObjC `CDVPlugin`): dispatch actions to the Insider SDK, return results, push callbacks to JS via document events.

## The rules that matter (read before editing)

1. **Single native call path.** Always `Utils.asyncExec(Constants.CLASS, reference, args)`. Never call `cordova.exec` directly.
2. **Validate first.** Every public method calls `Utils.checkParameters([{type, value}, …])` and bails via `Utils.showParameterWarningLog(...)` before any native call.
3. **Wrap errors.** `try/catch` → `Utils.asyncExec(CLASS, PUT_ERROR_LOG, [Utils.generateJSONErrorString(error)])`.
4. **Constants are central.** Native action names live in `js/Constants.js`. Add a new action there, then mirror the handler in **both** `src/android` and `src/ios`.
5. **Three-way parity.** A new public capability usually means: JS method + Android handler + iOS handler + a `types/*.d.ts` entry. Keep them in sync.
6. **Dates = epoch-ms strings.** Cross the bridge as `value.getTime().toString()` (no ISO).
7. **Platform guards.** Use `cordova.platformId`; platform-only methods silently no-op off-platform.
8. **Version sync on release.** `package.json`, `js/Constants.js` `SDK_VERSION` (`CDV-*`), `plugin.xml` pods, and `build-extras.gradle` pins move together.

## Testing

Jest 30 (`npm test`), node env, `babel-jest`. Tests in `__tests__/`; coverage from `js/**` only.

Two groups, reported as separate CI checks, selected by filename suffix via `jest.config.js` `projects`:

| Command | Group |
|---|---|
| `npm run test:unit` | everything except `*.integration.test.js` (subtractive) |
| `npm run test:integration` | `**/*.integration.test.js` |
| `npm test` | both — the sum must equal the two groups |

A test driving the production graph (`js/InsiderPlugin`, `js/InsiderAppCards`, `js/InsiderEvents`) MUST carry the `*.integration.test.js` suffix; `devops/check_test_groups.sh` enforces it in CI. Add/adjust a test with any behavior change (see [.claude/rules/unit-tests.md](../../.claude/rules/unit-tests.md) §0).
