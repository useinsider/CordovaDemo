# 🔌 API Documentation — cordova-plugin-insider

> Auto-generated by orbit init. Public plugin API. Links back to [ARCHITECTURE.md](./ARCHITECTURE.md); handler details in [CODE-CATALOG.md](./CODE-CATALOG.md).

This is an **npm package / Cordova plugin**, not an HTTP service — its "API" is the JavaScript surface exposed to host apps as the global `Insider` (clobbered from `js/InsiderPlugin.js`). Every call is marshaled over `cordova.exec` into native code.

## Call contract

```js
// Internally, every native call goes through:
Utils.asyncExec(InsiderConstants.CLASS, reference, args) // → Promise (cordova.exec)
```

- **className** is always `"InsiderPlugin"` (`Constants.CLASS`).
- **reference** is the native action name (e.g. `"itemPurchased"`) — see `js/Constants.js`.
- **args** is an array; objects are pre-serialized into typed `{key, type, value}` arrays via `Utils.parseObjectWithTypes`.
- Public methods validate inputs with `Utils.checkParameters` first; invalid input logs a warning and returns early (no native call).

## Initialization

| Method | Signature | Platform |
|--------|-----------|----------|
| `Insider.init` | `(partnerName: string, appGroup: string, handleNotificationCallback: function, appIdentifier?: string \| null)` | both (branches: iOS → `initWithLaunchOptions`, Android → `init`) |
| `Insider.initWithCustomEndpoint` | `(partnerName, appGroup, endpoint, handleNotificationCallback, appIdentifier?)` | both |
| `Insider.reinitWithPartnerName` | `(partnerName: string)` | both |

Every init action sends the same native argument array `[partnerName, sdkVersion, appGroup, customEndpoint\|null, appIdentifier\|null]`. `appIdentifier` is forwarded only when it is a non-empty string (native then calls its app-identifier initializer; on Android nothing is forwarded if the SDK was already initialized natively, because `init` returns early); otherwise the slot is `null` and the existing initializer runs. `reinitWithPartnerName` with a different partner name clears the app identifier.

`handleNotificationCallback` is registered on the `ins_notification_handle` document event; native fires it for `NOTIFICATION_OPEN`, `INAPP_BUTTON_CLICK`, `TEMP_STORE_PURCHASE`, `TEMP_STORE_ADDED_TO_CART`, `TEMP_STORE_CUSTOM_ACTION`.

## Event observer (`Insider.events`)

Observes events recorded by the SDK. One native observer is registered per process; JS-side
fan-out serves all subscribers.

| Method | Signature | Notes |
|--------|-----------|-------|
| `addObserver` | `(observer: (name, parameters, timestamp) => void) => { remove() } \| undefined` | Returns a subscription; `remove()` is idempotent. Returns `undefined` on invalid input |

The observer is called with three positional arguments — `name: string`,
`parameters: object`, `timestamp: number` — mirroring the native `onEventRecorded` callback
and the React Native / Flutter wrappers. There is deliberately **no bulk teardown**: each
subscriber owns its own `remove()`, so one integrator cannot unsubscribe another's observer.

⚠️ **`timestamp` is in WHOLE SECONDS since 1970, not milliseconds.** It is passed through from
native unchanged for parity. Use `new Date(timestamp * 1000)`. Note the contrast: `Date`
values *inside* `parameters` are epoch **millis**, per the plugin's bridge convention.
`parameters` is a read-only SDK-owned snapshot, **deep**-frozen before delivery (nested maps
and arrays included, cycle-safe) — do not mutate it.
Native actions: `addEventObserver` / `removeEventObserver` (persistent keep-callback stream).
